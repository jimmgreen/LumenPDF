# 真实鼠标双击：选择／文字工具原位编辑

日期：2026-09-23。范围：已有文字批注，在选择工具、文字工具以及阅读工作区的选择状态下，通过真实鼠标双击直接进入页内编辑。不新增批注类型，不修改 PDF 正文/OCR 范围。

## 根因与修正

此前的定向 GUI 检查直接投递 `WM_LBUTTONDBLCLK`，它能验证编辑回调，却绕过了真实鼠标识别。这台机器启用了 Mouse-in-Pointer：鼠标按下、移动和抬起进入 `HandlePointerClient`，该通路之前没有识别连续两次点击，所以仅有双击回调并不足以保证真实操作生效。

本轮同时修正：

1. **LUMEN Pointer 输入通路识别双击**：按系统双击时间、系统物理像素范围、同一存活控件和已完成的首击进行匹配；移动拖拽、异目标抬起、捕获取消和焦点离开不组成双击。弱引用避免命中已经销毁的控件。时间戳回绕有回归覆盖。
2. 鼠标／笔分别识别，不把不同输入来源拼成一组；触摸滚动仍保持既有行为。笔的实际手感不以本轮鼠标测试代替。
3. Pointer 已处理过的旧式双击消息去重，避免重复派发。
4. **进入编辑不再调用工作区／工具重置**。选择工具与文字工具保留各自状态，阅读工作区也不因编辑而自动打开右侧属性栏、重新适合页面或滚到页顶。
5. 来自页面双击的入口不主动滚动页面；只有非点击式入口才按既有需要定位视区。
6. 文字双击仅在选择／文字工具下启用；锁定批注、禁用画布和无关绘制工具不进入文字编辑。便签保留自己的编辑路径。

显示与编辑继续使用前轮的共享文字布局和 LumaText，不重新引入 RichEdit。

## 修改位置与边界

- `../LUMENUI/src/core/pointer_click.h`：可单独验证的点击序列状态机。
- `../LUMENUI/src/core/input_router.cpp`、`window_impl.*`：真实 Pointer 路由、取消、焦点与消息去重。
- `../LUMENUI/tests/visual/main.cpp`：点击配对、拖拽、时间／范围限制、控件销毁等回归。
- `app/application.cpp`：取消进入编辑时的工作区和工具重置。
- `app/canvas.cpp`：两种文字入口及禁用／锁定／无关工具防护。
- `tests/canvas_tests.cpp`、`tests/text_double_click_smoke.ps1`：应用和真实输入验证。

库改动逐文件先校验原 SHA，再执行带备份的字节补丁并校验写后 SHA。应用文件使用 MCP 版本保护补丁。不 reset、clean 或覆盖现有 LumaText 工作；PDF 保存与 worker 串行边界不变。
